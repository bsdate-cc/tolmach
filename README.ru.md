# Толмач

Диктовка для Windows: нажал кнопку на микрофоне (или горячую клавишу), сказал — текст напечатался
в окне, где стоит курсор. Распознавание идёт на вашем компьютере (GigaAM v3), в сеть ничего не уходит.

Распознаётся русская речь. Меню, вопросы и окошко есть на русском и английском.

**[Read in English](README.md)**

## Что умеет

- **Запуск диктовки** кнопкой на USB-микрофоне, горячей клавишей `Shift+Win+Q` или из меню в трее.
- **Живой текст.** Пока вы говорите, распознанное показывается в небольшом окошке; после остановки
  текст печатается в окно, которое было активным. Печать идёт нажатиями клавиш, поэтому работает и в
  окне удалённого рабочего стола; буфер обмена не трогается.
- **Пунктуация и числа** расставляет сама модель: «сорок минут» превращается в «40 минут».
- **Последний текст ещё раз:** `Shift+Win+Z` печатает последний распознанный текст повторно; из меню
  его можно ещё и скопировать.
- **Словарь терминов:** `Githab`, `GetHub` и `в гитхабе` пишутся `GitHub`, если слово есть в вашем
  словаре, — сравнение идёт по звучанию, а не по буквам.
- **Приглушение** других программ на время записи (по желанию).
- **Значок в трее** показывает состояние: ожидание, запись, распознавание, шлюз не отвечает.
- **Обновления** через git: когда в репозитории появляется новая версия, в меню появляется пункт
  «Обновить до X.Y.Z…». Само ничего не ставится.

## Как устроено

Два процесса. **Трей** — значок, запись с микрофона, окошко и печать текста. **Шлюз** — локальная
служба распознавания на `127.0.0.1`, говорит на подмножестве протокола OpenAI Realtime
(`WS /v1/realtime`) и принимает файлы (`POST /v1/audio/transcriptions`); доступ по ключу, из сети
шлюз не виден. Трей запускает шлюз сам и следит за ним.

## Что нужно

- Windows 10 или 11, 64 бита.
- [Python 3.12](https://www.python.org/downloads/) (64 бита) и [git](https://git-scm.com/).
- Микрофон. Кнопка на микрофоне — по желанию: без неё диктовка запускается горячей клавишей.
- Около 350 МБ на диске под модель.

## Установка

```
git clone https://github.com/bsdate-cc/tolmach.git
cd tolmach
tray.cmd
```

`tray.cmd` (двойной щелчок тоже работает) создаёт окружение `.venv`, проверяет Python, библиотеки,
настройки, модели, микрофон и шлюз. Чего не хватает — предлагает поставить: библиотеки через pip,
модели загрузкой. Затем запускает трей. Каждый шаг печатается в окне (по-английски) и пишется в журнал.

### Модели

Файлы моделей в репозиторий не входят. При первом запуске `tray.cmd` предлагает их скачать
(около 330 МБ) в `%USERPROFILE%\.tolmach\models`:

| Файл | Что это |
|---|---|
| `silero_vad.onnx` | определитель пауз Silero VAD |
| `gigaam-v3\gigaam_v3_e2e_rnnt_encoder_int8.onnx` | GigaAM v3, модель `e2e_rnnt` в формате ONNX |
| `gigaam-v3\gigaam_v3_e2e_rnnt_decoder.onnx` | |
| `gigaam-v3\gigaam_v3_e2e_rnnt_joint.onnx` | |
| `gigaam-v3\gigaam_v3_e2e_rnnt_tokens.txt` | |

GigaAM v3 опубликована SberDevices под лицензией MIT
([ai-sage/GigaAM-v3](https://huggingface.co/ai-sage/GigaAM-v3)). Файлы скачиваются из сборки
сообщества для [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) —
[Smirnov75/GigaAM-v3-sherpa-onnx](https://huggingface.co/Smirnov75/GigaAM-v3-sherpa-onnx), из одной
зафиксированной ревизии; `silero_vad.onnx` — из
[выпусков sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models). Каждый файл
сверяется с известной контрольной суммой SHA-256 и только потом кладётся на место. Скачать без окна
запуска: `.venv\Scripts\python -m tolmach.tray.models`.

**Своя модель.** Подойдёт любая, которую sherpa-onnx загружает как NeMo-трансдьюсер (энкодер,
декодер, joiner, токены): положите её файлы в папку моделей и назовите их в `config.json`, раздел
`gateway.model`. Окно запуска скачивает только файлы из таблицы выше; свои файлы вы кладёте сами.

## Как пользоваться

1. Поставьте курсор туда, куда нужен текст.
2. Нажмите кнопку на микрофоне или `Shift+Win+Q`. Появится окошко «Слушаю…».
3. Говорите. Нажмите ещё раз — текст напечатается.

Меню значка в трее: начать и остановить диктовку, скопировать или вставить последний текст, выбрать
микрофон, положение окошка и язык, приглушение других программ, автозапуск, управление шлюзом,
журналы, обновление.

**Кнопка микрофона.** Поддерживаются USB-микрофоны, чья кнопка шлёт нажатие по HID (страница
Consumer Control). По умолчанию настроен микрофон с `VID 1B3F`, `PID 2008`; для другого впишите его
идентификаторы в `client.button` в `config.json`. Такая кнопка обычно ещё и глушит микрофон
аппаратно — программа это учитывает.

## Словарь терминов

Модель слышит русскую речь, поэтому слова разработчика выходят верными по звучанию и неверными по
буквам: `Githab`, `GetHub`, `гитхаб`, `Word 3` вместо `worktree`. Словарь исправляет это после
распознавания: там, где распознанные слова **звучат** как термин, пишется сам термин — так, как он
записан в словаре.

Пункт меню «Открыть словарь терминов» создаёт `%USERPROFILE%\.tolmach\terms.txt` со стартовым набором
и открывает его в Блокноте. Строка — один термин:

```
GitHub
worktree = ворктри
main = мэйн, мейн
```

Если слово произносится так, как пишется, достаточно его самого. После `=` указывают русскими буквами,
как вы его говорите или как его пишет модель, — когда это не так. Правки подхватываются сразу; пустой
файл или его отсутствие выключает словарь.

Чего ждать. Слова русскими буквами — обычная речь, поэтому они заменяются, только когда звучат в
точности как термин, слово в слово: `гитхаб` и `в гитхабе` станут `GitHub`, а `бетон` не станет
`Python`. Там, где модель сама написала латиницей, — это её знак, что слово нерусское, — хватает
близкого звучания, и термин может быть разбит на части: `GetHub`, `Local Host`, `Whispery`. Короткий
термин (`git`, `pip`) берётся только из латиницы, потому что `гид` звучит так же. То, что не было
распознано, не добавляется никогда.

Если модель упорно пишет термин по-своему русскими буквами (`Гит Хаб`, `лакафост`), допишите это
написание в строку термина: `GitHub = гит хаб`.

Чего словарь не умеет: термин короче трёх звуков (`Go`, `C`) нужно задавать произношением
(`Go = голанг`); слово с цифрой внутри (`python3`) не трогается; термин, разрезанный паузой или знаком
препинания, не собирается. Слово, которое звучит в точности как термин, заменяется, даже если вы имели
в виду другое: `питон` всегда станет `Python`.

## Настройки

`%USERPROFILE%\.tolmach\config.json` (пункт меню «Открыть файл настроек»). Основное:

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `language` | `auto` | язык меню, вопросов и окошка: `ru`, `en` или `auto` (русский, если Windows или её региональный формат русские, иначе английский) |
| `client.microphone` | `""` | имя микрофона; пусто — микрофон с кнопкой, иначе системный |
| `client.hotkey` | `shift+win+q` | горячая клавиша диктовки |
| `client.insert_last_hotkey` | `shift+win+z` | печатает последний распознанный текст ещё раз; `""` — выключено |
| `client.insert_mode` | `type` | `type` — печать нажатиями, `paste` — через буфер обмена и Ctrl+V |
| `client.append_space` | `true` | пробел после вставленного текста |
| `client.overlay_position` | `center` | место окошка: `top-left` … `center` … `bottom-right` |
| `client.mute_other_apps` | `true` | глушить другие программы на время записи |
| `client.silence_autostop_s` | `60` | остановить запись после стольких секунд тишины |
| `gateway.port` | `8765` | порт шлюза на `127.0.0.1` |
| `autostart` | `true` | запускать трей при входе в Windows |

Все настройки и их значения по умолчанию — в `tolmach/config.py`.

Обе горячие клавиши и идентификаторы кнопки (`client.button`) читаются при старте трея; остальные
настройки `client` действуют со следующей диктовки.

## Где что лежит

- `%USERPROFILE%\.tolmach\` — настройки, словарь терминов (`terms.txt`), ключ шлюза, модели, журналы (`logs\tray.log`,
  `logs\gateway.log`, `logs\startup.log`). Переменная `TOLMACH_HOME` задаёт другую папку.
- Надиктованный текст и звук в журналы не пишутся. Запись, которую шлюз не успел распознать из-за
  сбоя, сохраняется в `failed\` — чтобы не потерять сказанное.

## Обновление

Трей при запуске и раз в шесть часов сверяется с репозиторием. Если есть новая версия, в меню
появляется «Обновить до X.Y.Z…»: по клику и подтверждению код обновляется (`git`, только перемотка
вперёд) и трей перезапускается. Обновление исполняет код из репозитория с вашими правами, поэтому
ставится только по клику. Рабочей копии с собственными правками обновления не предлагаются.

История версий — в [CHANGELOG.md](CHANGELOG.md).

## Разработка

```
.venv\Scripts\python -m pytest -q
```

Тесты не требуют моделей; три теста на настоящих моделях пропускаются, если нет моделей или файла
`tests\data\benchmark.wav`.
